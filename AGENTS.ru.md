# 1. Обзор проекта

## Цель

NiimBlue iOS — это нативное iOS-приложение для управления и печати этикеток на принтерах NIIMBOT.

Его цель — предоставить полный функционал веб-версии NiimBlue в нативной iOS-среде.

Репозиторий хранит только исходный код и конфигурацию.

Проект **не предназначен** для замены существующего веб-приложения NiimBlue.

---

## Основная цель

Начиная с пустого iOS-проекта, создание полностью рабочего приложения для печати этикеток должно требовать только:

1. Клонирования репозитория.
2. Запуска процесса сборки.

После сборки приложение должно содержать:

- полный UI на SwiftUI;
- CoreBluetooth-клиент для принтеров NIIMBOT;
- NSLocalSocket-клиент для USB-соединения;
- нативный редактор этикеток с множественными объектами;
- сохранение/загрузку этикеток;
- предпросмотр печати с постобработкой.

Процесс сборки должен всегда быть воспроизводимым.

# 17. Идиempотентность

Каждый процесс сборки и конфигурации в этом репозитории должен быть идиempotent.

Запуск той же сборки несколько раз никогда не должен:

- создавать дублирующие данные;
- портить существующую конфигурацию;
- производить неконсистентное состояние;
- требовать ручного cleanup.

Повторный запуск всегда должен приводить к одному из:

- никаких изменений потому что желаемое состояние уже достигнуто;
- безопасных обновлений, необходимых для достижения желаемого состояния.

Идиempотентность — обязательное требование для каждого процесса сборки в этом репозитории.

# 20. Стандарты кодинга

Проект намеренно следует консервативным стандартам кодирования.

---

## Swift Conventions

- Follow Swift Naming Guidelines
- Prefer value types over reference types
- Use explicit error types
- Prefer optional chaining over forced unwrapping
- Use result builders for dynamic UI

---

## SwiftUI Conventions

- Use View protocol for reusable components
- Use EnvironmentValues for shared state
- Use Binding for two-way binding
- Use @StateObject for owned objects
- Prefer composition over inheritance

---

## Service Layer

- Services should be testable
- Services should not depend on UI
- Services should use Combine for async operations
- Services should handle errors explicitly

---

## Naming

Используйте описательные имена.

Избегайте ненужных аббревиатур.

```swift

NiimbotBluetoothClient.swift
ImagePostProcessor.swift
```

Плохие примеры:

```swift
State.swift
Client.swift
Process.swift
```

Каждый файл должен выполнять одну логическую задачу.

Большие файлы должны быть разделены на меньшие.

---

## Readability

Понятный код предпочтительнее компактного.

Избегайте ненужной сложности.
